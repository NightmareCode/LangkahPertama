## Tech conventions (single-file static pages, no build step)

- Reveal-on-scroll: IntersectionObserver + `.reveal/.in`, disabled by `prefers-reduced-motion`, `<noscript>` fallback.
- Sheets/dialogs: focus trap, Escape close, focus restore (`lastFocus !== document.body` fallback), `sheet.focus()` delayed ~60ms.
- `esc()` covers `& < " '`. If ever composing wa.me text (main page only): `encodeURIComponent` EVERY segment, join with literal `%0A`.
- `Element.closest()` polyfill at top of scripts. rAF loops suspend on `document.hidden` + wake on `visibilitychange`; counters get a `setTimeout` completion guarantee.
- Themed `#toTop` on every page (shows after ~600px).
- **Never put `overflow-x: hidden` on `body`** — it forces body's `overflow-y` to compute to `auto`, making body a second scroll container → **double scrollbar** (user hit this on the /sites/ pages 2026-07-06). Guard horizontal overflow with `html { overflow-x: clip }` ONLY (`clip` doesn't create a scroll container); body needs no overflow rule.
- 3D: Three.js 0.160 **self-hosted** at `/assets/vendor/three@0.160.0/` (min build + GLTFLoader/RoomEnvironment/BufferGeometryUtils); importmap uses local root-absolute paths (`/assets/vendor/...`), NOT a CDN. `<script type="module">`, top-level await + try/catch hides container on failure. Blender MCP → GLBs in `assets/` (apply modifiers, name nodes). `touch-action: pan-y`.
- **"RTX"-style bloom glow (added 2026-07-06)** on the two ring pieces — the main `/` hero AND `/sites/apogee/`: a Three.js post-processing chain (`EffectComposer` → `RenderPass` → `UnrealBloomPass` → `OutputPass`) makes the emissive rings/gem-spark glow cinematically. Real-time WebGL can't do literal ray-tracing, so the "RTX look" = **UnrealBloom + a RoomEnvironment env-map for metallic reflections + `MeshPhysicalMaterial` (clearcoat) on the metals**. The post-processing module tree is **self-hosted** under `examples/jsm/postprocessing/` (Pass, EffectComposer, RenderPass, ShaderPass, MaskPass, UnrealBloomPass, OutputPass) + `examples/jsm/shaders/` (CopyShader, LuminosityHighPassShader, OutputShader) — fetched from unpkg@0.160.0 into the repo, so **CSP stays `'self'`** (no new origin). Wiring per page: `composer.render()` replaces `renderer.render()`; `composer.setSize(w,h)` added to the resize path; keep `renderer.toneMapping = ACESFilmic` (OutputPass applies it). Bloom params (Vector2, strength, radius, threshold): hero `0.24/0.35/0.85`, apogee `0.34/0.4/0.8` — deliberately SUBTLE (user feedback 2026-07-06: the first stronger pass was "too shiny, uncomfortable"); keep bloom a soft halo, never let glow swallow the geometry. The gem geometry (apogee `Core` = 80-facet crystalline icosphere, flat-shaded) was left as-is — sharp facets already maximise bloom sparkle; more subdivision would smooth it and reduce glints. Node-name contracts unchanged (apogee assigns materials by name-prefix in JS; hero uses exact `HeroRig`/`RingA…`).
- Branding: `assets/lp-mark-gold.png` (nav/footer), `assets/icon-512.png` (favicon), `assets/og-image.png` (1200×630; new URL busts WhatsApp preview cache). Wedding pages keep wedding branding.
- PWA/SEO: `manifest.json` + `/sitemap.xml` + `/robots.txt` at root; icons `assets/icon-192.png`, `assets/maskable-512.png` (Blender-rendered gold mark on a dark beveled tile, safe-zone padded), `assets/apple-touch-icon.png` (180). ## Security posture (hardened 2026-06-16)

Static site = small surface (no backend/DB/auth/cookies; "logins" are fake client-side demos). GitHub Pages can't set HTTP headers, so protections are meta-based.
- **CSP**: every page has a `<meta http-equiv="Content-Security-Policy">` (inserted right after `<meta charset>`). Base policy: `default-src 'self'`, `script-src 'self' 'unsafe-inline' https://cdn.jsdelivr.net`, `style-src ... https://fonts.googleapis.com`, `font-src https://fonts.gstatic.com`, `img-src 'self' data:`, `frame-src 'self'`, `object-src 'none'`, `base-uri 'self'`, `form-action 'self'`, `upgrade-insecure-requests`. **`'unsafe-inline'` is required** (pages are inline-script/style heavy; no nonces possible on Pages). The trading page has a WIDER variant adding `*.tradingview.com`/`*.tradingview-widget.com` to script/frame/connect/img. **Adding any new external origin (CDN/font/embed) means updating the CSP on that page or it silently breaks** — re-test the console for CSP violations after. The 6 Three.js pages (`/`, `/dashboard/`, `/sites/` + apogee/forma/ember) **self-host** Three.js and have jsdelivr REMOVED from their `script-src`/`connect-src` (tightened to `'self' 'unsafe-inline'` / `'self'`); only the safety page (Chart.js) and trading page (TradingView) still need a CDN origin in their CSP. The main page `/` additionally sets `frame-src 'self' https://airgas.my` for the live client-site embed inside `#work-showroom` (airgas.my sends no X-Frame-Options / frame-ancestors, so it's iframe-embeddable; verified). The embed iframe is **`position:absolute`** in `.lf-view` (so its 1280px width doesn't blow out the grid column), `pointer-events:none` behind a `.lf-guard` link that opens the live site in a new tab; a `scaleAir()` resize scaler mirrors the dashboard `dashFrame` (1280→container, IDs `airgasFrame`/`airgasView`).
- `<meta name="referrer" content="strict-origin-when-cross-origin">` on every page; `frame-ancestors`/HSTS/X-Frame/nosniff are header-only = NOT available on Pages (clickjacking is moot — no sensitive state).
- Chart.js (only external classic script) has SRI `integrity` + `crossorigin` (safety page). Three.js importmaps can't take SRI (spec) — rely on pinned `@0.160.0` + CSP allowlist. Pin every CDN version; never `@latest`.
- `CNAME` file pins the custom domain (prevents takeover if Pages settings reset). `.nojekyll` serves files verbatim. `/.well-known/security.txt` (RFC 9116, Expires 2027-06-16 — renew before then). Branded `404.html`. `.github/dependabot.yml` watches the Actions versions.
- Deploy workflow strips `CLAUDE.md` from the published artifact (keep internal docs out of the live site). NEVER commit real secrets/keys/.env — anything shipped to Pages is world-readable.
- No DOM-XSS sinks (all dynamic HTML from hardcoded data; user input is filter-only; `esc()` on the safety page covers `& < > " '`). Keep it that way: never feed `input.value`/`location.*`/`referrer` into `innerHTML`.

## Windows/PowerShell traps

- PS 5.1 reads BOM-less `.ps1` as ANSI → mojibake. Write scripts with UTF-8 BOM.
- `''` inside a double-quoted PS string stays literal — has injected broken JS before. Escape JS apostrophes as `\'` instead.
- Commit messages: `@'…'@` here-strings; embedded `"` in plain `-m "…"` splits args.
- Sandbox false-flags inline PS (`'RM '` parsed as `rm`): write to a temp `.ps1` and execute.
